# 11.1 Plan Mode vs Direct Execution

> 📅 2026년 04월 05일 기준  
> ⭐ **시험 빈출 — 판단 기준 암기**

---

## 두 모드 비교

| 항목 | Plan Mode | Direct Execution |
|------|----------|-----------------|
| 코드 변경 | ❌ (계획만) | ✅ (즉시 실행) |
| 사용 시기 | 대규모 변경 | 단순 변경 |
| 위험도 | 낮음 (검토 후 실행) | 높음 (즉시 실행) |
| 속도 | 느림 | 빠름 |

---

## Plan Mode 사용 기준

```
✅ Plan Mode 사용:
- 45개 이상 파일에 영향
- 아키텍처적 결정 필요
- 마이크로서비스 분리
- 라이브러리 마이그레이션 (예: Express → Fastify)
- 데이터베이스 스키마 변경
- 인증 시스템 전면 교체
```

## Direct Execution 사용 기준

```
✅ Direct Execution 사용:
- 단일 파일 버그 수정
- 명확한 스택 트레이스로 파악된 오류
- 간단한 함수 추가
- 변수명/함수명 변경 (단일 파일)
- 로컬라이제이션 문자열 추가
```

---

## 판단 흐름

```
변경 요청 받음
    ↓
몇 개 파일에 영향?
    ├─ 1-3개 → Direct Execution
    ├─ 10-30개 → 상황에 따라 (아키텍처 변경 여부)
    └─ 45개+ → Plan Mode

아키텍처 결정이 필요한가?
    ├─ 아니오 → Direct Execution
    └─ 예 → Plan Mode
```

---

## 잘못된 판단 예시

```
❌ 항상 Plan Mode: 시간 낭비
❌ 항상 Direct: 대형 변경 시 실수 위험

✅ 올바른 판단:
"import 문 하나 추가" → Direct (단순)
"전체 API v1→v2 마이그레이션" → Plan Mode (대규모)
```
