## 2.2 Opus, Sonnet, Haiku — 언제 무엇을 쓸까?

### 세 모델의 특성

```
Claude Opus 4.6  ─── 가장 강력한 추론, 복잡한 멀티스텝 작업
Claude Sonnet 4.6 ── 속도와 성능의 균형, 일반적인 프로덕션 워크로드  
Claude Haiku 4.5  ── 가장 빠르고 저렴, 단순 분류/추출 작업
```

### 모델 선택 의사결정 트리

```
작업이 무엇인가?
│
├── 복잡한 멀티스텝 에이전트 작업?
│   → Claude Opus 4.6
│
├── 일반적인 코드 생성, 분석, 요약?
│   → Claude Sonnet 4.6
│
└── 빠른 분류, 키워드 추출, 간단한 번역?
    → Claude Haiku 4.5
```

### 실무 활용 패턴

Opus + Haiku 조합 패턴 (비용 최적화)
```python
# 코디네이터: Opus (복잡한 판단)
# 서브에이전트: Haiku (단순 반복 작업)

coordinator = claude_opus_4_6  # 전략 수립, 복잡한 추론
document_classifier = claude_haiku_4_5  # 대량 문서 분류
data_extractor = claude_haiku_4_5  # 정형 데이터 추출
synthesizer = claude_sonnet_4_6  # 최종 보고서 생성
```

## 2.3 컨텍스트 윈도우와 토큰 이해

### 토큰이란?

토큰은 모델이 텍스트를 처리하는 단위입니다.

```
영어: "Hello world" → 2 tokens
한국어: "안녕하세요" → 약 3~5 tokens (한국어는 더 많은 토큰 필요)
코드: "def hello():" → 약 5~6 tokens
```

실용적 환산:
- 1,000 토큰 ≈ 영어 750단어 ≈ 한국어 500자
- 100만 토큰 ≈ 약 750,000 영단어 ≈ 책 약 1,500페이지

### 1M 토큰 컨텍스트의 의미

Claude Opus/Sonnet 4.6의 1M 토큰 컨텍스트 창은 혁신적입니다:

| 활용 사례 | 필요 토큰 |
|----------|----------|
| 일반 대화 | 1K~10K |
| 긴 이메일 스레드 분석 | 10K~50K |
| 대형 코드베이스 리뷰 | 100K~500K |
| 전체 소설 분석 | 200K~500K |
| 대규모 법률 문서 검토 | 500K~1M |

### ⚠️ Lost-in-the-Middle 효과

> 🎯 시험 출제 포인트!

컨텍스트가 길어질수록 중간 부분의 정보를 놓치는 현상이 발생합니다.

```
[시작 부분] ← 잘 기억됨 (높은 주의도)
[중간 부분] ← 놓칠 수 있음 ⚠️
[끝 부분]   ← 잘 기억됨 (최근 편향)
```

대응 전략:
- 중요한 정보는 컨텍스트의 시작이나 끝에 배치
- 섹션 헤더로 명확히 구분
- 핵심 사실은 별도 "facts block"으로 관리
