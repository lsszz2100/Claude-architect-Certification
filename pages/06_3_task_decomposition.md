## 두 가지 분해 전략

### 1. 프롬프트 체이닝 (Prompt Chaining)

```python
# 순차적, 고정 워크플로우
# 각 단계가 이전 결과에 의존

def report_pipeline(topic: str):
    # 1단계: 데이터 수집
    data = collect_data(topic)
    
    # 2단계: 분석 (수집된 데이터 필요)
    analysis = analyze(data)
    
    # 3단계: 보고서 작성 (분석 결과 필요)
    report = write_report(analysis)
    
    return report
```

**적합한 상황:**
- 순서가 명확한 고정 워크플로우
- 각 단계가 이전 결과에 의존
- 단계 수가 미리 알려진 경우

---

### 2. 동적 분해 (Dynamic Decomposition)

```python
# LLM이 판단하여 적응적으로 분해
# 주제마다 다른 분해 전략

COORDINATOR_PROMPT = """
주제: {topic}

먼저 이 주제를 분석하여 필요한 연구 영역을 파악하세요.
그런 다음 각 영역에 대해 Task를 스폰하세요.
영역의 수와 종류는 주제에 따라 달라집니다.
"""
```

**적합한 상황:**
- 주제마다 필요한 분석 영역이 다름
- 범위를 미리 알 수 없음
- 유연한 대응이 필요함

---

## ⭐ 범위 누락 주의 (시험 자주 출제)

```
❌ 잘못된 분해 (너무 좁음):
주제: "글로벌 AI 반도체 시장"
에이전트 A: 엔비디아만 분석
에이전트 B: 미국 시장만 분석
결과: AMD, 인텔, 삼성, TSMC, 아시아/유럽 시장 누락!

✅ 올바른 분해 (전체 범위):
코디네이터가 먼저 "글로벌"의 범위를 파악:
- 모든 주요 제조사 (엔비디아, AMD, 인텔, 삼성, TSMC)
- 모든 지역 (미국, 유럽, 아시아-태평양)
- 모든 세그먼트 (학습용, 추론용, 엣지)
그 후 각 영역별 서브에이전트 스폰
```

---

## 분해 품질 체크리스트

```
분해 전 코디네이터가 확인해야 할 것:

□ 전체 범위를 모두 커버하는가?
□ 각 서브에이전트의 책임이 명확한가?
□ 중복 없이 완전한 커버리지인가?
□ 서브에이전트 수가 적절한가? (너무 많으면 비효율)
```
