# 05.1 Hub-and-Spoke 아키텍처

> 📅 2026년 04월 05일 기준

---

## 개념

```
           ┌─────────────┐
           │  코디네이터   │  ← 중앙 허브
           │    (Hub)     │
           └──────┬───────┘
         ┌────────┼────────┐
         ▼        ▼        ▼
    ┌────────┐ ┌────────┐ ┌────────┐
    │에이전트A │ │에이전트B │ │에이전트C │  ← Spokes
    └────────┘ └────────┘ └────────┘
```

핵심 규칙: 서브에이전트끼리 직접 통신 ❌
코디네이터가 모든 정보 흐름 관리 ✅

---

## Hub-and-Spoke의 장점

```
1. 명확한 책임 분리
   - 코디네이터: 오케스트레이션
   - 서브에이전트: 전문 실행

2. 제어 가능성
   - 모든 정보가 코디네이터를 통과
   - 단일 관찰 포인트

3. 확장성
   - 새 서브에이전트 추가 용이
   - 코디네이터 로직 변경 불필요

4. 격리성
   - 서브에이전트 실패가 다른 에이전트에 영향 없음
```

---

## 대안 아키텍처와 비교

```
Hub-and-Spoke (권장):
코디네이터 → A, B, C (중앙 제어)

피어-투-피어 (복잡):
A ↔ B ↔ C (통제 어려움)

파이프라인:
A → B → C (순차, 병렬 불가)
```

---

## 언제 Hub-and-Spoke를 사용하는가?

- 여러 독립적인 작업이 필요할 때
- 결과를 통합해야 할 때
- 작업 간 조정이 필요할 때
