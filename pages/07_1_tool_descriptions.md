# 7.1 툴 설명(Description)의 중요성

> 📅 2026년 04월 05일 기준  
> ⭐ 시험 핵심 개념

---

## 왜 툴 설명이 중요한가?

```
툴 설명 = LLM이 어떤 툴을 호출할지 결정하는 1차적 메커니즘

좋은 설명 → 올바른 툴 선택 → 정확한 결과
나쁜 설명 → 혼동 → 잘못된 툴 호출 → 오류
```

---

## 나쁜 툴 설명

```python
# ❌ 최소한의 설명
{
    "name": "get_customer",
    "description": "고객 정보를 가져옵니다.",
    "input_schema": {"type": "object"}
}

# ❌ lookup_order도 마찬가지
{
    "name": "lookup_order",
    "description": "주문 정보를 가져옵니다.",
    "input_schema": {"type": "object"}
}

# 결과: LLM이 두 툴을 혼동하여 잘못된 것을 호출
```

---

## 좋은 툴 설명

```python
# ✅ 상세하고 구분된 설명
{
    "name": "get_customer",
    "description": """이메일 또는 전화번호로 고객 계정 정보를 조회합니다.
    
    사용 시점:
    - 고객 신원 확인이 필요할 때
    - 주문 처리 전 계정 상태 확인
    
    입력 형식:
    - email: "user@example.com" 형식
    - phone: "+82-10-1234-5678" 형식 (둘 중 하나 필수)
    
    반환: customer_id, name, tier, account_status
    
    주의: lookup_order나 process_refund 전에 반드시 먼저 호출
    lookup_order와 구별: 이 툴은 고객 정보, lookup_order는 특정 주문 정보
    """,
}
```

---

## 좋은 툴 설명의 요소

```
포함할 것:
✅ 사용 시점 (언제 이 툴을 써야 하는가)
✅ 입력 형식 (어떤 값을 넣어야 하는가)
✅ 반환 값 (어떤 정보를 얻을 수 있는가)
✅ 비슷한 툴과 구분 (언제 이것을 쓰고 언제 다른 것을 쓰는가)
✅ 전제 조건 (다른 툴 먼저 호출 필요 등)
✅ 엣지 케이스 (예외 상황)

제외할 것:
❌ 내부 구현 상세
❌ 코드 내용
❌ 불필요한 배경 정보
```

---

## 시험 핵심

```
툴 선택 오류 문제 → 정답: 툴 설명 개선 (first step)

절대 틀리지 말 것:
- 툴 선택 오류의 근본 원인 = 부족한 설명
- Few-shot 추가보다 설명 개선이 먼저
- 라우터 추가보다 설명 개선이 먼저
```
